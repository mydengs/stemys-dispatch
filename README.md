# 入口域名分发系统 · Go

**用途**：防 GFW 及省级防火墙屏蔽入口域名、防各大厂商（腾讯/QQ浏览器、UC、手机厂商自带浏览器等）安全爬虫采集入口站点信息导致域名被打标屏蔽的「发射/分发」入口系统。

工作方式：多入口域名承接 → 按渠道(utm/微信/QQ/抖音)、地域、设备分流 → 302 到落地页（支持泛域名 + **每个访客随机前缀**）→ 滑块人机闸门 → 记录点击 → 后台看数据；并提供带 **HMAC 签名 + 有效期 + 次数上限** 的分享链接。

> 防封/防采集三层：
> 1. **域名池**：入口域名批量导入，被封就在后台「停用」换下一个（域名+campaign 绑定即时生效）；
> 2. **滑块验证闸门**：入口先出验证页，302 跳转只在真实浏览器（能执行 JS、通过滑块）后才发生——非 JS 爬虫跟不进跳转链，采不到落地域名池；
> 3. **爬虫伪装页（decoy）**：识别为爬虫/安全探测/浏览器 prefetch 的请求直接看到中性「维护公告」页，不出验证弹窗、不出 302、noindex，采集不到分发行为；厂商爬虫 UA 在后台可自定义补充。
>
> 原型参考目录 `../redirect-lab` 中未搬入的部分：按天换入口子域、按秒过期链接（需要 DNS/证书自动签发与监控配套，可作为后续扩展）。

## 功能

| 模块 | 说明 |
|------|------|
| 多域名承接 | 后台登记域名，每个域名绑定一个 `campaign`；访客经该域名进来只用对应 campaign 的落地页分流 |
| 渠道分流 | 优先读 `utm_source`；否则按 UA/Referer 识别 微信 / QQ / 抖音 / 直连 |
| 地域分流 | 读 `CF-IPCountry` / `X-Country-Code` 等 CDN/nginx 注入的国家码（未知为 ZZ） |
| 设备分流 | mobile / tablet / desktop |
| 规则匹配 | campaign + 设备 + 国家 + 渠道，`priority` 高者优先，同级 `weight` 权重随机（可做 A/B）；campaign 在落地页表单里是**下拉选择**（选项实时从域名池生成、标注代表域名，防手滑打错；旧值/池外值有「当前值」兜底选项不会被覆盖） |
| 泛域名落地 | 落地地址可直接填 URL，也可写泛域名根（`a.b.com` / `*.a.b.com`）+ 路径；前缀支持两种模式：**每次访问随机**（每个访客拿到不同的 `随机字母数字.a.b.com`）或固定前缀（🎲 一键生成） |
| 点击统计 | 每次访问落库（设备/国家/渠道/utm/来源/UA/IP哈希），后台概览 + 明细 |
| 反作弊 | 识别常见爬虫/无 UA 流量，标记为 bot，不计入有效率 |
| 人机验证 | 进入分发入口前先出「向右滑动」滑块验证（暗色安全验证弹窗），通过后签发 2h 通行 cookie；可在配置里关闭 |
| 防采集伪装 | 爬虫/厂商安全探测/浏览器 prefetch 请求 → 直接返回中性「维护公告」页（无验证弹窗、无 302、noindex）；UA 关键字后台可自定义，命中落库可观察 |
| 分享链接 | `HMAC 签名（防篡改）+ 有效期 + 访问次数上限（防刷）`，适合私域/KOL 专属追踪 |
| 后台 | 登录鉴权、域名/落地页/分享链接 CRUD、数据看板、改密 |

## 快速开始

```bash
cd dispatch
make tidy      # 拉依赖
make build     # 生成 ./dispatch
mkdir -p devdata
./dispatch config.json
# 打开 http://127.0.0.1:8801/admin   默认 admin / admin123 （登录后立即改密）
```

首次运行会自动建库建表、创建默认管理员。

**上线前务必**：改 `config.json` 里的 `secret`（固定成一段长随机串，否则重启后旧分享链接全部失效）、改默认管理员密码。

## 后台使用流程

1. **域名**：添加承接域名（如 `shop.example.com`），填 campaign（如 `双11`）。
2. **落地页**：加若干落地页，填 URL、campaign（要和域名一致）、设备/国家/渠道、priority、weight。
3. 用 nginx 把域名反代到本服务（见 `nginx.conf.example`），访问 `https://shop.example.com/?utm_source=wechat` 即按规则 302 到对应落地页。
4. **分享链接**：为某落地页生成带有效期的分享链接，发给私域/KOL，后台能看到每个链接的访问量。

分流规则示例：

| 落地页 | campaign | 设备 | 国家 | 渠道 | priority | weight |
|--------|----------|------|------|------|---------:|-------:|
| 移动-微信版 | 双11 | mobile | * | wechat | 10 | 1 |
| 移动-抖音版 | 双11 | mobile | * | douyin | 10 | 1 |
| 移动-通用版A | 双11 | mobile | * | * | 5 | 1 |
| 移动-通用版B（A/B）| 双11 | mobile | * | * | 5 | 1 |
| 桌面兜底 | 双11 | desktop | * | * | 1 | 1 |

### 泛域名落地（`*.a.b.com`）

落地地址有两种填法：

- **直接 URL**：`https://shop.example.com/activity/a`
- **泛域名**：填「泛域名根」`a.b.com`（或 `*.a.b.com`，会自动去掉 `*.`）+「路径」`/baidu`，再选前缀模式：
  - **每次访问随机前缀**（默认推荐）：每个访客进来现场生成一个全新的 `字母+数字` 前缀（8~11 位），
    访客 A 可能拿到 `uybwwq0g.a.b.com/baidu`，访客 B 拿到 `kcfva6ln529.a.b.com/baidu`——**人人不同**；
    后台「点击明细」会记录每个访客实际跳转的落地地址，可核对。
    前缀匹配对**每个访客独立成立**：A、B 两个访客首次进入各拿各的全新前缀，互不相同、互不影响。
    另有「**落地地址有效时间**」开关（默认关）：关闭 = 任何人每次进来都重新随机；开启并选时长后，
    仅「该访客本人」在有效期内回访沿用**他自己的**前缀（每次回访自动续期，即「访问后 N 时间内有效」），超期再来才换全新的。
    访客身份凭入口域下发的签名 cookie（`lp`，HMAC 防篡改、HttpOnly）识别，不依赖 IP（换网络也延续）；开关关闭时残留 lp 会被顺手清除。
    直连非 80/443 端口调试时浏览器 Host 会带端口，引擎匹配登记域名前已自动剥除端口。
  - **固定前缀**：所有访客共用同一个前缀（点 🎲 可一键生成一个，如 `asfsdg112t`）。

前缀只是"名字随机"，落地内容完全相同（都落到 `a.b.com` 泛解析指向的那台落地站 + 指定路径）。

要让这套生效，你需要：

1. **DNS 泛解析**：`*.a.b.com` → 你的服务器 IP（随机模式下这是硬前提，因为前缀不可预知）；
2. **泛域名证书**（如 Let's Encrypt `*.a.b.com`）+ 落地服务器 vhost 通配承接所有子域（nginx `server_name *.a.b.com;`）；
3. 本系统只负责**把访客 302 到该地址**，落地内容由那台落地站提供。

**承接域名也支持泛域名**：域名表里可直接登记 `*.a.b.com`，之后任何 `xxx.a.b.com` 的访问都会归到它绑定的 campaign（深层 `q.q.a.b.com` 也匹配，取后缀最长的规则）。

## 分流判定顺序

`Host → 域名表取 campaign`（未登记则 campaign 为空）→ 过滤 enabled 且 campaign 匹配的 offer →
按 `设备`、`国家`、`渠道` 过滤 → 取最高 `priority` → 同级按 `weight` 加权随机 → 302 到 URL。

## 反作弊说明

- 常见爬虫 UA（bot/spider/curl/headless 等）标记 `bot=1`，看板“有效率”只算非 bot。
- IP 以 SHA-256 哈希存储，不落明文，兼顾统计与隐私。
- 需要更强风控（点击去重、IP 频率限制、设备指纹）可在此基础扩展。

## 人机验证（滑块）

进入分发入口与分享链接（`/` 等非 `/admin` 路径，含 `/s/`）时，若未持有通行 cookie，先返回暗色「安全验证」弹窗页：
标题 + SSL加密/安全防护/隐私保护三图标 + 黄色圆形滑块（"向右滑动验证"）。用户拖到最右后：

1. 前端采集拖动轨迹（pointer 采样，25ms 节流）连同 `challenge id` + 进度比例提交到 `/captcha/verify`；
2. 服务端四重校验：比例 ≥ 97%、距挑战创建 ≥ 400ms、**轨迹质量**（≥8 个采样点、跨 ≥450ms、逐段位移有变化——拦两点瞬移与匀速直线脚本）、未过期一次性；
3. 通过则签发 HMAC 签名通行 cookie `hum`（有效期 2 小时），随后 `location.reload()` 进入正常分流；此后 2 小时内同一浏览器不再验证。

- 关闭验证：`config.json` 设 `"disable_captcha": true` 并重启。
- 相关接口：`GET /captcha/challenge`（拿 id）、`POST /captcha/verify`（校验发 cookie）。
- 说明：这是「拖到底」式的轻量人机验证，能挡掉大部分无头脚本/爬虫；若对抗更强的自动化，可后续接入点选/拼图/极验等。

## 防采集伪装（decoy）

针对厂商安全爬虫/探测（QQ/微信安全中心、微信分享链接卡片预览、UC、vivo/三星/苹果等自带浏览器的「秒开」预取与安全检测）与通用爬虫，四层判定：

- **IP/CIDR 黑名单（最硬）**：后台每行一个 CIDR（`blocker_cidrs`，已预置腾讯云等公告段）。厂商云侧检测来自机房 IP，真实用户来自家宽/4G——命中 IP 段**无条件伪装，UA 伪装失效**（按「点击明细」观察继续补充）；注意 `X-Forwarded-For`/`CF-Connecting-IP` 透传真实访客 IP，nginx 反代时必须正确设置。
- **UA 关键字（通用）**：内置 bot/spider/crawler/无头工具等规则 ＋ 后台每行一个补充关键字（包含匹配）。
- **厂商探针 UA（内置，专治不含 bot 字样的抓取器）**：`TencentSecurityTicker`（QQ浏览器安全检测）、`QQExternal`、`WeChatShareLinkNewSmartPreview`/`WeChatURLSecurityTicker`（微信分享卡片预览/链接安全）、`GoogleOther`、`WhatsApp/`、`ChatGPT-Agent`、`SkypeUriPreview`、`LinkPreview` 等，见 `internal/dispatch/engine.go` 的 `vendorProbeSubstrings`。
- **预取/探测请求头与方法**：`Purpose/Sec-Purpose/X-Purpose` 值为 `prefetch|unload|preview|instant|display|unsafe-url` 的浏览器预取（三星/vivo/Safari 链接预览等）算探测；**HEAD、OPTIONS 试探一律按探测处理**（链接检测器偏爱 HEAD 跟 302，真实浏览器导航只有 GET）。

命中后返回**中性页**（200、无验证弹窗、无 302、`X-Robots-Tag: noindex`），采集方看不到分发行为与落地域名；`/s/` 分享链接同样先过「伪装 → 滑块」双闸门才给 302，厂商爬虫探分享链接也吃不到落地跳转：

- 未自定义文案时，内置 **4 套不同风格模板随机轮换**（维护公告/系统升级通知/站点信息/资讯速览），页面指纹不固定；
- 后台「设置 → 防采集伪装」填了「伪装页标题」才固定使用自定义文案（正文可空）；清空标题即恢复模板轮换；
- 每次命中落库（`clicks.landing='decoy'`、`bot=1`），「点击明细」即「谁在采我」观测面板；
- 开关：`anti_crawl_enabled`（默认开），改动即时生效无需重启。
- 入口卫生：`GET /robots.txt` 恒返 `Disallow: /`、全站响应带 `X-Robots-Tag: noindex`（验证页/伪装页不会被搜索引擎收录）；`/favicon.ico` 直供透明小图标——两者都不进分发逻辑、不记点击（修掉「访客开页 + favicon 被计两次点击」的双计问题）。
- 渠道归因加固：微信/QQ/抖音 webview 的 `X-Requested-With` 包名头（`com.tencent.mm` 等）参与渠道判定，X5 内核改写 UA 时仍可正确归因。

**运维套路**：投放新入口域名 → 看点击明细里高频且从不完成验证的 UA/IP → IP 进 CIDR 列表、UA 特征进关键字列表 → 入口对厂商探测呈现轮换公告页，对真实访客照常验证+分发。某入口被防火墙封：后台「停用」该域名，启用池里下一个（域名池批量导入），投放链接换域名即可。

## 网络类型闸门（只放行运营商真实接入）

按出口 IP 判断访客是否「运营商接入」——≈真实家宽/4G/5G，与云机房/政企专线/教育网/VPN 出口区分。三层判定（优先级从高到低）：

1. 机房黑名单 `blocker_cidrs` → **deny**（爬虫伪装规则本来就先命中它）；
2. 运营商白名单 `carrier_cidrs` → **carrier**（已预置电信 AS4134、联通 AS4837/AS9929、移动 AS9808、鹏博士、长城宽带的 IRR 公告前缀聚合表约 1743 条，含 `240e::/20`、`2408:8000::/20`、`2409:8000::/21` 等 IPv6 大段；广电/教育网/企业专线不在默认表内，按需补充）；
3. 都不命中 → **other（白名单外）**。

模式（后台「设置 → 网络类型闸门」三选，`site_config.carrier_gate`）：

- `关闭`：不判定；`观察`（默认）：照常放行，只在「点击明细→网络类型」列记录分类；
- `严格`：白名单外访客**一律吃伪装页**，连验证弹窗都不给（deny 类本就走爬虫伪装）——新干净域名上线的标准姿势。

**新域名投放套路**：严格模式下 GFW/厂商机器人从机房 IP 来 → 永远只能看到轮换公告页；真人从运营商接入 → 验证+分发。先用「观察」跑几天，把明细里「白名单外」却像真人的网段（能过验证、有落地点击）补进白名单（如广电、教育网、公司专线用户群），再切「严格」。

**能力边界（诚实声明）**：同一运营商池内，4G/5G 基站出口与家宽**无法用 IP 精确区分**（两者共享公告前缀段）；挂在运营商线路上的 IDC 会被算进白名单（由机房黑名单兜底）。能可靠区分的是「运营商接入 vs 非运营商出口」。

## 部署

见 `nginx.conf.example`（反代 + 传 Host/国家头）和 `deploy/dispatch.service`（systemd）。
生产建议：

- 后台 `/admin` 用独立子域 + IP 白名单，或加 HTTP Basic 认证再暴露公网；
- 默认 `listen` 是 `0.0.0.0:8801`（对外可访问）。若只想让本机 nginx 反代访问，把 `config.json` 的 `listen` 改回 `127.0.0.1:8801`；
- 直连暴露时记得在防火墙放行端口（本机用 ufw）：`ufw allow 8801/tcp`；
- `secret` 固定写死并保密；
- 数据库放持久盘并定期备份 `*.db`；
- 前面挂 HTTPS（域名证书）。
